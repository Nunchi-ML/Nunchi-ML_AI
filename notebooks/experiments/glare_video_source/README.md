# 해가 정면에 낮게 있던 도로 사진 찾기 (모델 ② 데이터 · G 확인용)

GLARE(미국 블랙박스 2,157장)에는 **찍은 시각 · 위치가 없어서** 해 높이와 방향을 알 수 없어요.
촬영 시각 · GPS · 카메라 방향이 함께 있는 사진을 찾아, 계산한 해 위치로 "해가 정면에 낮게 있던" 장면을 고릅니다.

| 쓰임 | 내용 |
|---|---|
| 모델 ② | 한국 도로 사진으로 학습 · 검증 사진 늘리기 (2인 라벨) |
| 모델 ③ G 확인 | 해 높이 · 방향 차이 Δ 와 실제 눈부심 단계의 관계 → 재혁님 공식 G 가 맞는지 |

## 데이터 후보 (2026-11-02 확인)

|---|---|---|---|
| **Mapillary** (채택) | ✅ 사진마다 | 무료 개발자 토큰 | 대구 도로 포함. 사진 CC BY-SA 4.0 (출처 표기) |
| BDD100K | ✅ (info JSON) | ❌ 공식 다운로드 서버(dl.cv.ethz.ch)가 없어짐 | 거울 사이트에도 GPS 파일 없음 |

| AI Hub 자율주행 영상 | (확인 필요) | 신청 · 승인 | 한국 도로 |

## 실행

1. https://www.mapillary.com/dashboard/developers 에서 앱 만들고 **Client Token** 복사
2. AI 폴더 `.env` 에 한 줄 (git 에 안 올라감): `MAPILLARY_TOKEN=...`
3. ```bash
   pip install -e .
   python notebooks/experiments/glare_video_source/find_sun_frames.py --route ../FE/src/data/dalgu.json
   ```
4. 결과 `data/glare_mapillary/candidates.csv` (git 제외)

| 열 | 뜻 |
|---|---|
| `captured_at_kst` · `lat` · `lon` · `heading` | 촬영 시각(한국시간) · 위치 · 카메라 방향(북=0) |
| `sun_alt` · `sun_az` | 그 시각 · 위치의 해 높이 · 방위 (`nunchi_ml.sun`, pvlib) |
| `gap` | 해 방위 − 카메라 방향 차이 Δ (0 = 정면) |
| `front_low` | 정면 저각도 (해 높이 0~25° · Δ ±25°) — 모델 ① · ③ 과 같은 기준 |
| `sequence` | 연속 촬영 묶음 → 검증 때 **묶음 단위로 나누기** (같은 영상 사진이 학습 · 시험에 섞이지 않게) |

### 블랙박스 추가 세트 (`download_dashcam_set.py`)

보정한 블랙박스 여행(2019-02-24 16:03~16:23, 달구벌대로 서쪽 방향)에서 3초 이상 간격으로 **160장** (정면 저각도 139 · 4묶음, 16.3 MB).
훑어본 결과 정면 저각도 사진은 해가 실제로 화면 위쪽 가운데에 있고, Δ 40° 사진은 해가 화면 끝 · 밖 → 보정이 맞음.
라벨러용 `dash_pack.zip` (사진 + 블라인드 시트 + `label_tool.html`). 한 날 한 차 사진이라 **검증 때 이 세트는 한 덩어리**로 다룰 것.

**라벨 결과 (성진 1인, `analyze_dashcam.py`)** — 해 높이 20~24° 로 거의 같아서 **Δ 만의 효과**가 보임.
방향 기록 오류(GPS 경로 방향과 45° 넘게 다름, `fix_metadata.py` 의 `heading_suspect`) 6장 빼고 154장:

| Δ (해 − 진행 방향) | 0~5° | 5~10° | 10~15° | 15~20° | 20~25° | 25~35° | 35~60° |
|---|---|---|---|---|---|---|---|
| 사진 | 37 | 39 | 37 | 16 | 10 | 4 | 10 |
| 눈부심(1 이상) | 97% | 95% | 84% | 75% | **30%** | 0% | 50% |
| 심한 눈부심(2) | 65% | 56% | 38% | 19% | 10% | 0% | 0% |

- Δ 가 커질수록 눈부심이 단계적으로 줄고, **20~25° 에서 크게 떨어짐** → 모델 ① · ③ 의 "정면 ±25°" 문턱이 블랙박스 화면 기준으로 맞음
- 심한 눈부심은 Δ 15° 안쪽에 몰림 → G 를 단계(정면 0~15° / 15~25° / 그 밖)로 나누는 근거
- Δ 와 라벨 순위 상관 −0.53. 화면 특징 중엔 도로 선명도 · 밝기 · 대비(+0.3) 정도
- 한계: 한 날 · 한 차 · 1인 라벨. 35~60° 의 50% 는 해가 화면 밖인데 하늘이 하얀 사진 (0/1 기준 애매한 곳)

(사진 속 해를 자동으로 찾아 시각을 고르는 방법도 해 봤지만, 나뭇가지 사이 하늘 · 흰 간판을 해로 잘못 잡아서 버림)

아직 1인 라벨이라 카파 없음 → 같은 171장을 범수님이 따로 라벨 (`drive_pack.zip`).

## 라벨

1. `label_tool.html` 을 크롬으로 열기 (더블클릭) → `data/glare_mapillary` 폴더 고르기 → 이름 적기
2. 사진 보고 키보드 `1` 정상 · `2` 눈부심 · `3` 심한 눈부심 · `X` 제외(운전 시점 아님 · 깨짐), 애매하면 `U`
   - 무작위 순서 · 해 위치 · 그룹은 숨김 (화면만 보고 판정). 진행은 브라우저에 자동 저장
   - 기준은 화면 오른쪽 표 = 노션 분석계획서 「모델 ② 라벨 기준표」. **두 사람은 상의하지 않고 따로**
3. 다 하면 `CSV 저장` → `labels_<이름>.csv` 를 `data/glare_mapillary/` 에 넣기 (두 사람이 **같은 298장**을 보도록 사진 폴더는 한 사람이 받은 것을 압축해서 나눔 — 다시 검색하면 결과가 조금 달라질 수 있음)
4. 두 파일이 모이면
   ```bash
   python notebooks/experiments/glare_video_source/compare_labels.py
   ```
   → 일치율 · 카파(지난번 GLARE 0.20) · 합의 라벨 `labels_merged.csv` · 다시 볼 사진 `labels_disagree.csv`
   · 그룹(정면 / Δ 25~45° / 비교군)별 눈부심 비율 — 정면 저각도에서 눈부심이 확실히 많아야 해 위치 기준(G)이 맞는 것
