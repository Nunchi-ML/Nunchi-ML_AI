## 0. 한 줄 요약

> 터널 입구 사진 한 장과 그 순간의 해 높이 · 구름으로 **"이 터널에 들어갈 때 눈이 어둠에 적응하기 얼마나 힘든가(하 · 중 · 상)"**를 맞힌다.
> 처음 보는 카메라(Mapillary) 입구 66장에서 **위험도 F1 .844 (95% 범위 .70\~.97), '상' 재현율 1.00**.
> 이전 주 모델(.526)과 물리 공식(.427)은 확실히 이기고, 해 높이 하나로 만든 2단계 규칙(.789)과는 **비슷**하다.

## 1. 이 모델이 답하는 질문

- 모델 ③의 질문은 "어느 자리 · 어느 시각에 사고가 나나"가 아니다.
- **"태양 일조량 때문에 순응 부담이 생기는 터널 입구에서, 그 순간 위험도가 얼마인가"**를 맞힌다.
- 위험도는 **휘도비(터널 바깥 밝기 ÷ 터널 안 밝기)** 등급이다. 휘도비가 크면 동공이 따라가지 못해 입구 안쪽이 순간적으로 안 보인다.
- 입구만 다룬다(암순응). 이유:
  - 어두워질 때 적응이 더 느리다(PsPM 63% 도달: 어두워짐 1.5초 vs 밝아짐 0.36초).
  - 사고 분석(case-crossover)에서도 진입 쪽만 경향이 있었다(1.16\~1.29배).
  - 학습 데이터(71786)에 출구 사진이 0장이다.
  - 출구 역광 눈부심은 모델 ②의 몫으로 남긴다.

## 2. 전체 흐름

```
[입구 사진] ──► 사진 숫자 10개 ─┐
[촬영 시각·위경도] ──► 해 높이 ──┼──► ① 직선 회귀(Ridge) ──► 추정 바깥 밝기 log10(L20) ──┬──► 동공 모델(SpectroSense)에 전달
[가까운 ASOS] ──► 구름(전운량) ─┘                                                     │
                                  └──────────── 12개 + 추정 밝기 = 13개 ─────────────────┘
                                                        │
                                                        ▼
                                  ② 2단계 로지스틱
                                     1단계: 하 vs 위험(중·상)
                                     2단계: 중 vs 상 (위험 사진만으로 학습)
                                                        │
                                                        ▼
                                           입구 위험도 등급  하 · 중 · 상
```

- ①은 "사진 → 바깥 밝기" 고리를 지키고, 동공 모델에 넘길 밝기를 만든다.
- ②는 등급을 **바로** 맞힌다. 밝기를 먼저 맞히고 공식으로 등급을 내면 작은 밝기 오차가 등급을 뒤집기 때문이다(4절).

## 3. 정답 만드는 법

모델은 정답을 사진에서 만들지 않는다. **촬영 시각 · 위치의 위성 일사량**으로 만든다. 71786과 Mapillary 모두 같은 방법이다.

| 단계 | 계산 | 근거 |
|---|---|---|
| ① 일사량 E | 촬영 시각 · 위경도 → 천리안2A 일사량 (MJ/m², 다음 정시 1시간 값) | 기상청 API허브 |
| ② 바깥 밝기 | L20 = E × 277.8 × 126 × 0.15 ÷ π (cd/m²) | 일사량→조도 126 lm/W, 도로·주변 반사율 0.15 |
| ③ 조광 단계 | L20 ÷ 4,000을 25% 단위로 올림 (25 · 50 · 75 · 100%) | 국토부 터널 조명 지침 6.6.1 |
| ④ 터널 안 밝기 | 입구 = 280 × 조광 단계 | 지침 (280 = 4,000 × 0.07) |
| ⑤ 휘도비 | L20 ÷ 터널 안 밝기 | |
| ⑥ 등급 | 10배 미만 하 · 10\~15배 중 · 15배 초과 상 | Schreuder 1991 문헌값 (원문 미확인). 사고 데이터로 점검(EXP-56): 데이터 경계보다 안정적이라 유지 |

- 조광 단계 때문에 등급은 밝기에 대해 **톱니 모양**이다. 예: L20 700\~1,000이면 중, 1,000\~1,400이면 다시 하.
- 시각 · 위경도는 정답 만들기와 해 높이 계산에만 쓴다.

## 4. 왜 이 구조인가 (실험으로 거쳐 온 길)

| 실험 | 날짜 | 구조 | 핵심 결과 | 배운 것 |
|---|---|---|---|---|
| EXP-55 | 11/4 | 밝기 회귀 → 공식 등급 | Mapillary 안에서 LightGBM+ .75 | 사진 규칙은 찍기보다 못함, 정답 ASOS라 임시 |
| EXP-55b | 11/5 | 같음, 천리안 정답 | 사진 안 쓴 ML .78 ≈ 규칙5 .79 | 해 높이 하나가 정답과 상관 .93 |
| EXP-55c\~e | 11/5 | 같음, 사진분류 반영 | 사진 ML .67 > 사진 규칙 .41\~.45 | 입구가 보여야 사진이 쓸모 있음. 경계 근처 사진이 2/3 → F1 불안정 |
| EXP-67 | 11/5 | 같음, 71786 학습 → Mapillary 시험 | 튜닝 부스팅 입구 F1 .526, 물리 공식 .427과 비슷, '상' 재현율 .62 | 처음 보는 카메라에서 사진 규칙은 무너짐. 그러나 회귀 구조로는 .5대에서 막힘 |
| EXP-88 | 11/5 | 같음, 도로 사진 추가 | 누수 정정 후 효과 없음 | 같은 여정 사진 걸러내기 필요 |
| **EXP-93** | 11/6 | **등급 바로 맞히기 · 2단계** | 2단계 로지스틱 .824 → 추정 밝기 넣어 **.844** | **점수를 올린 것은 튜닝이 아니라 구조** |
| EXP-94 | 11/6 | 구조 교차 (ML 구조 ↔ 규칙 구조) | 같은 틀에서 ML이 규칙을 +.266으로 이김 | 이긴 이유는 "데이터로 배운 밝기" |

- 같은 부스팅 회귀를 F1 기준으로 다시 튜닝하면 오히려 .526 → .490으로 떨어졌다. 하이퍼파라미터 문제가 아니었다.
- 회귀 구조는 밝기를 꽤 맞혀도(R² .60) 등급 F1이 .53에 머물렀다. 톱니 모양 공식 때문에 경계 근처에서 등급이 뒤집혔다.

## 5. 모델 상세

### 5-1. 입력 숫자 13개

**사진 숫자 10개** (사진 한 장에서 계산, 0\~1로 맞춘 밝기 기준)

| 이름 | 뜻 |
|---|---|
| sky_mean | 위 1/3(하늘) 평균 밝기 |
| blue_sky | 하늘 중 파란 하늘 비율 |
| white_ratio | 하얗게 날아간 칸 비율 |
| shadow_contrast | 아래 1/3(도로)에서 밝은 곳 − 어두운 곳 = 그림자 진하기 |
| road_mean | 도로 평균 밝기 |
| sky_road_ratio | 하늘 ÷ 도로 밝기 |
| portal_ratio | 터널 구멍 주변 ÷ 구멍 밝기 (로그). 71786은 구멍 다각형 라벨, Mapillary는 가운데 가장 어두운 15%. 터널이 안 보이는 학습 사진은 빈칸 |
| saturation | 색 진하기 |
| spread | 사진 전체 밝기 퍼짐 |
| mean_all | 사진 전체 평균 밝기 (카메라 자동 노출 영향 큼) |

**사진 밖 숫자 2개**

| 이름 | 뜻 |
|---|---|
| 해 높이 | 촬영 시각 · 위경도로 계산한 태양 고도(°) |
| 구름 | 가장 가까운 ASOS 관측소 전운량(0\~10) |

**13번째: 추정 바깥 밝기** = 5-2의 ① 출력

- **달(월)은 뺐다.** 넣으면 F1이 .329로 무너진다. 학습은 8\~9월뿐이고 시험은 12월 · 5월이 대부분이라 달 값이 엉뚱하게 쓰인다.

### 5-2. ① 바깥 밝기 추정: 직선 회귀

| 항목 | 값 |
|---|---|
| 모델 | Ridge 회귀, α = 10 |
| 입력 | 사진 숫자 10개 + 해 높이 + 구름 (12개) |
| 정답 | log10(L20) |
| 전처리 | 빈칸 → 학습 쪽 중앙값, 표준화 |
| 새는 길 막기 | 학습 사진의 추정 밝기는 **학습 안 장면 단위 5겹 OOF 값만** 쓴다. 자기 정답을 본 모델의 밝기를 ②에 주면 ②가 밝기를 실제보다 믿게 된다. 정답 밝기 자체는 입력에 넣지 않는다 |
| 새 카메라 성능 | 시험 입구 66장 R² **.77** (부스팅 회귀 .60, 물리 공식 .39) |

### 5-3. ② 등급: 2단계 로지스틱

| 항목 | 값 |
|---|---|
| 1단계 | 학습 사진 전부로 "하 vs 위험(중 · 상)" 로지스틱 회귀 |
| 2단계 | 학습 사진 중 위험(중 · 상)만으로 "중 vs 상" 로지스틱 회귀 |
| 예측 | 1단계가 하면 하, 아니면 2단계 결과 |
| 입력 | 13개 |
| 전처리 | 빈칸 → 학습 쪽 중앙값 → 표준화 → 등급 수 차이를 맞추는 가중(class_weight = balanced) |
| 규제 세기 | C ∈ {0.01, 0.1, 1, 10} 중 **학습 안 장면 5겹 OOF Macro F1**로 고름 → **C = 0.01** (OOF .696) |
| 시험 사진 사용 | 고를 때 한 번도 안 봄. 마지막에 한 번 채점 |

**1단계 가중치 (표준화 기준, 큰 순)**

| 숫자 | 가중치 |
|---|---|
| 추정 바깥 밝기 | **+.95** |
| 해 높이 | +.84 |
| 구름 | −.29 |
| 파란 하늘 비율 | +.25 |
| 그 밖 | 작음 |

→ 모델은 **추정 밝기를 가장 크게 쓴다.** 밝기 고리가 실제로 일을 한다.

(참고: 밝기를 넣기 전 2단계 로지스틱의 가중치는 1단계 해 높이 1.51 · 구름 −.48 · 파란 하늘 .33, 2단계 해 높이 1.67 · 구름 −.64 · 파란 하늘 .43 · 도로 밝기 .25였다.)

### 5-4. 12월을 학습 없이 맞힌 이유

- 학습(71786)에는 12월 사진이 없다.
- 모델은 달이 아니라 해 높이와 밝기로 판단한다. 12월 낮 해 높이 19\~27°는 8\~9월 아침 · 저녁 사진에도 있고, 그때 정답은 대부분 하다.
- 로지스틱은 직선 관계라 그대로 이어 쓴다. 나무 모델(부스팅 회귀)은 12월 정확도 .27에 그쳤다.

## 6. 데이터와 채점

시험 종류 ②a: **71786만으로 학습 → 한 번도 안 본 카메라(Mapillary)로 시험.**

| 항목 | 내용 |
|---|---|
| 학습 | AI Hub 71786 전국 도로시설물 영상 **3,624장** (2023년 8\~9월, 카메라 XNB-8003 1기종, 날씨 라벨 전부 맑음). 터널 입구 1,927장 + 터널 없는 고속도로 1,697장. 겨울 · 봄 0장, 출구 0장 |
| 학습 정답 분포 (입구 1,927장) | 하 274 · 중 1,069 · 상 584 |
| 시험 | Mapillary 172장 → 쓸 수 있는 118장(터널 안 · 분류 불일치 · 지하차도 · 밤 제외) → 입구 · 출구 93장 → **주 판정 입구 66장 (51장면)** |
| 시험 사진 분류 | 사람이 직접 분류 (최재혁 2회 + 팀원 1회, 공통 20장 일치율 0.9) |
| 시험 정답 분포 | 하 28 · 중 9 · 상 29 |
| 시험 달 분포 | 12월 22 · 5월 28 · 9월 11 · 6월 2 · 3월 · 4월 · 10월 각 1 |
| 주 지표 | 입구 66장 3등급 **Macro F1** (하 · 중 · 상 F1을 같은 무게로 평균) |
| 95% 범위 | 장면 51개를 1,000번 다시 뽑기(bootstrap) |
| 이김 기준 | 짝지은 F1 차이의 95% 하한 > 0 (모델 ②와 같은 기준, 11/5 결정) |
| 보조 지표 | 등급별 재현율 ('상' 재현율 = 진짜 상을 상으로 경고한 비율) |
| 뺀 것 | 출구(학습 0장, 시험 27장 중 23장이 상이라 판정 안 함). 규칙5 계절 · 구름 표(71786이 8\~9월뿐이라 다른 계절 칸이 빔) |

| 대 밝기 없는 2단계 | .696 | .691 | +.004 (−.004\~.013) | 비슷 |

**읽는 법**
- 대표 모델의 틀(추정 밝기 + 2단계)에 규칙 밝기(물리 공식)를 넣으면 .581로 떨어진다. **데이터로 배운 밝기(R² .77)가 핵심**이고, 이것이 ML을 쓰는 가장 강한 근거다.
- 규칙에 12개 숫자를 다 줘도 규칙은 결국 해 높이 하나만 골랐다. 그래서 가장 좋은 규칙 = 해 높이 경계 2개(.789).
- 같은 카메라(71786)에서는 대표 모델이 그 규칙을 이긴다(+.055, 하한 .025). 새 카메라 66장에서는 좋아지는 경향(+.057)만 있고 확정은 아니다.

### 7-4. 블랙박스(실제 차 카메라) 확인 (사례 수준)

- 입구 3건 중 2건, 아침 날짜 3일 중 2일을 맞혔다.
- 11월 아침은 해 높이 20\~30°로 낮아 거의 다 '하'로 냈고, 맑은 날 '중'을 놓쳤다.
- 블랙박스 사진은 팀 밖에 공유하지 않고 숫자만 적는다.

## 8. 약점 (정직하게)

1. **직선 밝기를 고른 데 판단이 들어갔다.** "학습 OOF 1등" 규칙으로는 부스팅 밝기안(OOF .78)이 뽑힌다. 부스팅은 같은 카메라 안에서만 잘 맞고 새 카메라 R²는 .60이라 직선(R² .77)을 골랐다. 시험 결과를 보고 고른 셈이라 발표에서 밝힌다.
2. **해 높이 규칙 · 밝기 없는 안과 비슷하다.** 차이 범위에 0이 들어간다. 정답이 위성 일사량에서 나오고, 일사량은 대부분 해 높이 · 구름으로 정해지기 때문이다. "사진이 더하는 몫"은 해 높이 + 구름 대비로만 유의하다(+.126).
3. **시험이 계절로 갈린다.** 12월 22장은 전부 하, 5월 28장은 전부 상이다. 대표 모델은 두 묶음을 다 맞혔고, 어려운 나머지 16장 정확도는 .69로 이전 회귀와 같다. F1 .84의 상당 부분은 "겨울 · 늦봄 구분"이다.
4. **'중' 등급이 약하다.** 시험 '중'은 9장뿐이고 재현율이 .44\~.56 수준이다.
5. **등급과 추정 밝기가 어긋나는 사진이 있다.** 대표 모델 등급과 "추정 밝기를 그대로 공식에 넣은 등급"의 입구 일치율 62%. 동공 설명에 쓰는 밝기와 위험도 등급이 다를 수 있다.
6. **후보를 여러 개 같은 시험으로 봤다.** 구조 비교 18개, 밝기 조합 9개. 1등 점수에 운이 섞인다. 그래서 주 모델은 학습 OOF로 고르는 원칙을 지켰다(결과도 1등 동일).
7. **시험 구름 칸 1/3이 비어 있다** (입구 22장). 해 높이 + 구름 모델이 해 높이만 모델보다 낮게 나온 원인일 수 있다.
8. **학습 데이터의 빈틈.** 71786은 8\~9월 · 맑음 · 카메라 1기종 · 출구 0장. 등급 경계 10/15배는 문헌 원문 미확인.
